# TestMona 用例脑图工作台 PRD

版本：1.1  
日期：2026-10-29  
状态：合并需求基线，待按阶段实现

产品版本规划：V1 编辑基础 → V1.1 业务闭环 → V1.2 AI 增强。本文档版本 V1.1 与产品交付版本分别编号。  
适用范围：TestMona Web 测试用例库、评审与测试执行  
需求来源：用户提供的能力清单及本次对话确认的实现方向。MeterSphere V3 作为体验参考，本文不声明已核实其全部产品行为或版本信息。

## 1. 背景与目标

当前项目提供独立脑图、节点编辑、现有用例关联以及基础 XMind 导入导出。用户仍需先在用例库创建完整用例，脑图主要承担组织和跳转作用。

本需求将其升级为“用例脑图工作台”：测试人员可按模块在脑图内直接编写真实用例，并使用同一批数据完成列表查看、评审、执行及缺陷关联。

核心目标：

1. 脑图创建和修改的用例立即成为用例库数据，无需人工复制。
2. 列表与脑图使用相同套件、目录、用例、权限及业务规则。
3. 评审结论对应用例版本；执行结果对应具体运行，均可追溯。
4. 保留现有独立脑图与历史关联，不强制转换或破坏数据。
5. 串联需求、用例、评审、测试计划、执行与缺陷，减少重复维护。
6. 在用户确认下由 AI 生成、补全和优化场景。

目标用户包括测试工程师、测试负责人、开发工程师和产品经理；具体操作取决于项目授权。

## 2. 用户与主要场景

| 用户 | 场景 | 期望结果 |
| --- | --- | --- |
| 测试人员 | 按模块展开功能点，直接创建用例、填写步骤和预期 | 切换列表即可看到相同用例 |
| 评审人员 | 按模块或单用例评审，提出意见并查看修改 | 评审结论、意见及对应版本可追溯 |

| 测试负责人 | 查看模块用例数量、评审和执行进度 | 能定位未评审、失败、阻塞等待处理用例 |

## 4. 信息架构与页面

### 4.1 入口与模式

- 编写：测试管理 → 测试用例 → 脑图视图；提供“列表 / 脑图”切换，默认以当前测试套件为根。项目范围可作为导航汇总根，其下先按套件组织，避免把不同套件目录混在一棵业务树中。
- 评审：用例库脑图提供评审模式；沿用当前数据范围并切换操作及状态展示。
- 执行：测试计划选择具体测试运行后进入脑图；运行详情也可直接切换脑图。
- 自由脑图：保留现有项目脑图入口，明确与用例脑图的用途区别。

### 4.2 布局

- 顶部：项目、当前套件/运行、视图切换、编辑/评审/执行入口、搜索筛选、撤销重做、自动排版、适应画布、缩放、导入导出、AI 入口、保存状态。执行入口未选择运行时先进入上下文选择。
- 左侧：按套件组织的模块导航，展示模块用例数，支持搜索、展开折叠、新增、重命名、移动；点击模块在画布聚焦定位。
- 中间：可缩放、平移、折叠、适配视图的画布；节点显示类型、标题、编号及当前模式状态。
- 右侧：选中模块显示概览与批量操作；选中用例显示基本信息、前置条件、步骤/预期、标签、优先级、维护人、关联需求、接口测试关联、缺陷、评论、附件、评审历史及变更记录；按模式和权限显示操作。接口测试关联先盘点当前系统能力，V1.1 需明确引用对象、查询与权限校验，不以静态占位替代实现。
- 窄屏：详情以抽屉展示，可关闭回到画布；关键操作通过可点击菜单提供。
- 空状态：提供创建模块、创建用例、导入入口；无权限时仅展示允许的操作。

### 4.3 节点结构

```text
测试套件
└── 模块/目录
    ├── 子模块
    │   └── 用例
    └── 用例
```

根默认对应套件，模块对应现有目录，一条用例节点对应一条真实用例。项目汇总根仅用于导航。用例不可作为模块或其他用例的父节点。

| 节点类型 | 含义 | 可包含的内容 |
| --- | --- | --- |
| ROOT | 当前套件；项目汇总时先展示套件 | 模块或未分目录用例；项目汇总下为套件 |
| MODULE | 真实目录 | 子模块、用例 |
| CASE | 真实测试用例 | 前置条件、步骤、备注的字段节点 |
| PRECONDITION | 用例前置条件字段 | 文本或现有富文本内容 |
| STEP | 真实结构化步骤 | 对应预期结果 |
| EXPECTED | 步骤预期结果字段 | 文本或现有富文本内容，无业务子节点 |
| NOTE | 用例备注字段 | 文本或现有富文本内容 |

字段节点是对应业务字段的可编辑投影，不创建另一套步骤或用例。步骤保持稳定标识与顺序；不能把步骤拖成模块或独立用例。复杂富文本及图片可进入右侧编辑，画布展示摘要。

## 5. 功能需求

### F01–F03 创建与编辑

1. 选中套件或模块，通过菜单、工具栏或快捷键创建模块/用例。
2. 新用例继承当前项目、套件和目录，使用现有必填校验、默认值及编号规则。
3. 双击节点编辑标题；详情面板支持用例现有字段，至少包含标题、前置条件、步骤描述、预期结果、优先级。
4. 步骤支持新增、删除、排序；前置条件、步骤、预期及备注支持节点行内编辑，保存时同步结构化字段，右侧与画布不得相互覆盖。优先复用现有编辑组件及校验。
5. 新建前未确认的内容为本地草稿；取消不创建空用例。确认成功后显示服务器分配的编号。
6. 修改内容明确显示“未保存 / 保存中 / 已保存 / 保存失败”。失败保留草稿并允许重试。
7. 切换视图、节点、模式或离开页面前，存在未保存内容时提供保存、放弃、取消；保存失败不得自动离开。

### 用例字段与保存规则

- 正式用例必须有标题、项目和套件。脑图新建时必须有模块归属；允许根下新建时先选择或创建模块。历史未分目录用例仍展示在“未分目录”分组，可移动到模块，不强制迁移。
- Case ID 为系统生成的必有稳定标识，用户无需填写，不作为可选业务字段。
- 可编辑字段包含项目现有优先级、测试类型、前置条件、步骤、预期、标签、维护人、关联需求、附件和备注。复用现有校验，不另造一套必填规则。
- 服务端保存成功才显示“已保存”，记录修改人、时间及变更字段；用 revision/version 或等价并发控制检测冲突，保留草稿并提供重新加载或人工比对合并。

### F04 节点操作

| 操作 | 业务语义 |
| --- | --- |
| 新增同级/子级 | 按节点类型创建合法层级；用例下只能创建前置条件、步骤、备注字段节点 |
| 拖动模块 | 更新真实目录父级，检查同套件及防循环规则 |
| 拖动用例 | 修改真实用例所属目录；编号与历史保留 |
| 复制用例 | 创建新编号，复制可编辑内容；不复制评审结论、执行结果及缺陷关系 |
| 剪切/粘贴用例 | 移动原用例，不创建副本；成功前原归属不丢失 |
| 删除用例 | 明确确认后软删除并进入回收站；列表与脑图均隐藏，保留历史引用 |
| 删除模块 | 空模块可确认删除；非空模块默认阻止，先移动内容，不提供隐式递归删除 |

首版支持用例复制/剪切/粘贴；模块复制包含子目录与用例，确认时显示影响数量，批量失败需展示逐项结果，重试不得重复创建已成功项。模块剪切等同移动目录。根节点不可复制、移动或删除。跨套件、跨项目剪切移动不在本次范围内。V1.1 提供显式“复制到项目”：检查源读取和目标创建权限、目标套件/目录、优先级/类型/自定义字段映射及附件访问，预览不兼容项；目标生成新 ID，不复制执行和评审历史，也不建立隐式跨项目关联。普通粘贴不能自动触发跨项目复制。

撤销/重做覆盖尚未提交的编辑和节点删除，可恢复未提交的误删。已提交删除通过回收站恢复；已提交内容通过变更历史选择版本并创建新的修订，不改写旧版本。恢复时检查权限、版本冲突、套件/目录是否仍存在，不能隐式复活已删除的上级对象。提审与执行结果不能通过画布撤销。V1 交付删除回收与恢复；V1.1 补齐历史版本恢复。

### F05 快捷键

| 快捷键 | 行为 |
| --- | --- |
| Tab | 按节点约束新增子级；模块下默认用例，用例下默认步骤，步骤下创建预期，其他类型不适用时提示 |
| Enter | 新建同类型同级节点；根节点不适用 |
| C | 在当前模块创建用例；选中用例时使用其所属目录 |
| M | 在当前套件/模块创建子模块；选中用例时使用其所属目录 |
| Ctrl/Cmd+C、X、V | 复制、剪切、粘贴 |
| Space | 编辑当前节点 |
| Delete / Backspace | 按删除规则请求确认；字段节点删除修改对应字段 |
| Ctrl/Cmd+F | 聚焦工作台搜索 |
| Ctrl/Cmd+S | 保存当前编辑 |
| Ctrl/Cmd+Z、Shift+Z | 对适用的未提交操作撤销/重做 |
| S / E / B | 仅执行模式：通过 / 失败 / 阻塞 |

快捷键仅在画布或明确的工作台控件获得焦点时生效。输入框、标题编辑、富文本、输入法组合输入或弹窗编辑期间，单字母及结构操作快捷键不得触发。菜单与帮助面板展示快捷键；无权限时快捷键不能绕过限制。覆盖画布库冲突键位，保留浏览器及编辑器必要行为。

### F06–F07 优先级与视图切换

- 使用项目现有优先级配置，不固定另一套等级；名称和颜色与列表一致。
- 列表与脑图保持当前套件、目录、搜索和筛选条件，切换不复制数据。
- 筛选结果保留必要祖先模块，标明筛选状态；模块计数区分当前匹配数量与总数量。
- 跨分页加载时不得只展示列表当前页而误称完整模块。大范围使用分支加载或明确加载提示。
- 列表修改后，脑图重新进入或刷新读取最新数据；首版不要求实时多人推送。

### F08 XMind、Excel 与 JSON 导入导出

XMind 提供标准模板：模块 → 用例 → 前置条件、优先级、步骤 → 预期结果。模板必须带说明及样例。

导入流程：上传 → 解析预览 → 确认节点映射 → 选择目标套件/目录 → 查看重复项与警告 → 确认提交 → 查看结果。

- 普通文件不能可靠区分模块与用例时，要求用户选择用例层级或逐项映射，不静默猜测入库。
- 预览不创建用例；导入默认创建新数据，可跳过重复项。
- 更新已有用例必须显式选择，通过可信标识、目标项目、权限和版本校验；同名不代表同一用例。
- 提交和失败重试具备幂等保护，返回逐项成功/失败及原因。
- 支持当前已接入的新旧 XMind 解析能力；首版仅处理首个工作表，其他工作表明确提示未导入。
- 导出当前完整范围或明确选择的筛选范围，包含模块、用例、前置条件、步骤、预期和优先级。
- V1.1 图片采用文件内可解析的附件形式；不支持的图片或属性在预览中提示，不静默丢失。
- 导出再导入后核心业务字段保持一致；不要求布局完全一致。
- 校验文件类型、大小、压缩展开体积、路径及节点限制；不执行附件或抓取不受信任远程资源。具体阈值实施时统一前后端并显示给用户。

Excel 与 JSON 规则：

- Excel 提供模板及字段映射，步骤使用可逆的结构化表格格式，不将多步骤与预期混成不可解析纯文本。
- JSON 提供带格式版本的导入和导出，使平台导出的结构化数据可校验、可重新导入；不是数据库原始转储。
- 三种格式统一支持预览、必填/标识校验、新增/跳过/显式更新、幂等与逐项结果，返回新增、更新、跳过、失败数量。
- 导出范围支持项目全量、指定套件/模块和筛选结果；项目全量保留套件边界，权限不足时明确提示范围。
- 同批次重复 ID 默认报冲突，必须在预览解决后提交，不按文件顺序静默覆盖。文件内 ID 不直接作为可信更新授权。

### F09 图片

- 在用例详情或步骤中上传、预览、替换、删除图片，复用现有附件存储与访问控制。
- 画布提供缩略图或图片标识，点击可预览；刷新与视图切换后仍可访问。
- 上传失败保留编辑内容并可重试；文件限制使用项目统一规则。
- 用例复制可复用受控附件引用，不产生跨项目访问；移除一处引用不能误删其他用例仍使用的图片。

### F10 AI 生成与增强

基础流程：选模块 → 输入需求或选择现有需求 → 生成草稿 → 编辑/选择 → 确认入库 → 更新脑图。已有生成服务可提前复用，不因此把 V1.2 增强能力标记完成。

V1.2 支持：

- 输入 PRD、自然语言需求、OpenAPI、现有用例或当前模块；关联现有文件解析与 AI 提供方，不静默获取外部内容。
- 输出结构化模块、标题、前置条件、步骤、预期及建议优先级；优先级映射到项目配置。
- 补充正常、异常、边界、权限与安全场景，检查重复用例，根据需求变化建议更新。
- 差异预览分别展示新增、修改、删除建议、重复或冲突；删除建议不自动执行，按原有删除规则确认。
- 用户可逐项编辑、接受或拒绝。确认前不写正式用例；重试不重复入库。
- 修改建议绑定生成时的用例版本，确认时再次检查权限和冲突，不能覆盖生成后的人工作业。
- 记录 AI 来源、引用需求、操作人和变更；需求覆盖分析展示已有关系及建议缺口，AI 建议不能冒充已验证覆盖。

复用现有 AI 提供方、生成与重复检测能力；生成用例归属选定套件/目录，脑图只展示成功入库数据。

### F11 评审

评审以任务组织：包含名称、关联用例范围、发起人、评审人、单人/多人模式、截止时间和任务状态；任务下按用例及版本记录轮次与结论。任务状态汇总各用例结果，不能将部分通过显示为全部通过。

- 单人模式仅指定一名评审人，以当前有效轮次内最后一次有效结论为准；结束轮次后重新评审创建新轮次，不覆盖历史。
- 多人模式所有有效评审人通过才通过，任一要求修改则不通过；其余未完成时为待评审。
- “有建议”为意见提示，可与结论同时存在，不作为一个会覆盖通过/不通过的互斥状态。

- 支持单用例及模块范围批量提审，提交前展示用例数量和范围。
- 指定一名或多名有项目访问权限的评审人；记录轮次、提交人、评审人、时间、意见、结论及用例版本。
- 基线规则：所有指定评审人通过则通过；任一要求修改则进入需修改；未完成意见显示待评审。
- 评审人可查看详情、填写意见、通过或要求修改；评审中修改评审人需有权限并记录历史，取消人员的历史意见保留且不计入当前结论。
- 用例内容变更不改写已完成轮次；新版本需发起新轮次。
- 项目提供“内容变更后需重新评审”设置。启用时，标题、前置条件、步骤、预期结果及附件变更触发需重审；优先级、目录、标签和画布布局变更不触发。未启用时仍显示评审针对的版本及当前版本差异。
- 模块显示待评审、通过、需修改等数量；批量操作展示逐项结果，不能将无权限或失败项标记成功。
- 现有普通用例状态与评审状态分别展示；详细映射在开发前盘点，不能把单个 approved 状态当作完整评审记录。

### F12–F13 执行、缺陷与报告

- 必须明确当前测试运行、环境及轮次；无运行上下文的用例库脑图不能写执行结果。
- 节点对应当前运行中的用例执行记录，而非直接把结果写到用例库。
- 支持未执行、通过、失败、阻塞、跳过及项目已有执行状态；若已有模型缺少跳过，需统一扩展列表和报告，不能仅在脑图增加展示值；步骤结果、实际结果、备注、执行人及时间复用现有执行模型。
- S/E/B 写入成功后更新节点及汇总，失败恢复原状态并允许重试；快捷操作也记录审计。
- 模块只汇总当前运行内的后代用例，筛选时明确显示筛选影响。
- 测试计划存在多次运行时必须先选运行；相同用例的不同环境、运行及轮次结果互不覆盖。
- 执行使用可追溯的用例版本/快照；用例库修改不能悄悄改写历史执行内容，若现有能力不足需补齐。
- 用例执行详情可关联已有缺陷或创建缺陷，绑定当前执行结果并保留用例追溯；创建成功但关联失败时可重试关联，避免重复创建缺陷。
- 脑图结果与运行列表、测试计划统计及现有报告一致，复用现有报告入口。

## 6. 数据与兼容性原则

1. 目录、用例、步骤、优先级、附件以现有业务记录为唯一事实来源；脑图视图仅保存布局、折叠及展示偏好。
2. 业务标识与画布节点标识稳定映射，不能使用标题作为唯一标识。
3. 新增评审记录及必要版本关系；执行继续归属运行及执行结果，不另建一套脑图执行数据。
4. 现有自由脑图及一节点关联多用例的模型继续可用，不自动转换或删除。
5. 提供自由脑图转用例结构的预览入口：明确模块映射，将关联用例展开为独立节点；写入目录归属前显示移动影响并确认，原脑图保留。无法无损转换的节点必须提示。
6. 所有批量写入明确事务边界及逐项结果；重复提交、超时后重试不得重复创建。
7. 多人编辑用版本校验检测覆盖冲突，提示刷新、比对并保留本地草稿；本期不做自动合并。

## 7. 权限、审计与质量要求

- 复用项目和现有业务权限，服务端再次检查；只读用户不能通过画布、快捷键、导入或接口写入。测试负责人、测试工程师、产品经理等是业务使用身份，不据此新增或硬编码角色；实施时将查看、创建/编辑、删除/恢复、评审、执行、导入/导出逐项映射到当前 RBAC，缺失能力在对应阶段补齐。产品经理默认不授予执行和删除，额外授权遵从项目角色配置。
- 评审与执行权限分别检查，跨项目对象与已删除对象拒绝操作。
- 创建、修改、移动、删除、提审、结论、执行结果及缺陷关联纳入现有审计链。
- 中文和英文文案同步；状态除颜色外还提供文字或图标说明；菜单及详情可键盘访问。
- 空数据、加载、保存失败、权限变化、网络中断、目标被删除均有可理解提示。
- 大量用例避免一次挂载全部节点，采用折叠/分支加载且保证计数准确。V1 完成前确定并记录基准设备、规模及加载/交互指标，不能仅凭少量节点宣布性能通过。
- 规模目标：500 个可见节点时可完成常规平移、缩放与编辑；5,000 条用例可按模块分段加载。上述为目标规模，验收前必须记录设备、浏览器、数据构成、首次可操作时间及交互延迟阈值，未明确阈值不得以“流畅”宣告通过。
- 浏览器支持 Chrome、Edge、Safari 当前主流稳定版本；每次验收记录具体版本，覆盖快捷键和附件行为。
- 复用现有画布库前验证节点定制、事件、快捷键和图片支持；若存在能力阻塞，先提交选型结论再更换依赖。

## 8. 验收标准

| 编号 | 场景 | 通过标准 |
| --- | --- | --- |
| AC01 | 脑图创建模块、子模块及用例 | 列表显示相同层级和编号；刷新数据不丢失 |
| AC02 | 编辑标题、前置条件、步骤、预期、优先级 | 列表详情与脑图一致；步骤顺序正确 |
| AC03 | 列表编辑后切回脑图 | 读取更新后的同一条用例，无副本 |
| AC04 | 拖动、复制、剪切、粘贴 | 移动保留编号，复制生成新编号；非法层级和跨项目移动被拒绝；显式跨项目复制按 AC20 验收 |
| AC05 | 删除非空模块/已有用例 | 非空模块阻止；用例软删除入回收站，可恢复；历史与其他对象不被误删 |
| AC06 | 快捷键及输入法 | 非编辑状态正确触发；输入文本时不误创建、删除或执行 |
| AC07 | 未保存切换及保存失败 | 可保存、放弃、取消；失败保留草稿且不静默离开 |
| AC08 | 搜索、筛选及分页范围 | 两种视图范围一致，祖先路径和匹配/总计数准确 |
| AC09 | 标准 XMind 导出再导入 | 模块、用例、前置、步骤、预期、优先级及支持的图片一致 |
| AC10 | 普通/异常 XMind | 映射可确认；不支持内容有警告；恶意或超限文件被拒绝 |
| AC11 | 图片及 AI 生成 | 刷新保留图片；AI 确认前不入库，重试不重复创建 |
| AC12 | 单条/模块评审 | 评审人、结论、意见、轮次和版本可追溯；批量范围准确 |
| AC13 | 修改已评审用例 | 开启设置时内容变更触发需重审；历史结论不改写 |
| AC14 | 脑图执行及 S/E/B | 当前运行结果与列表、汇总、报告一致；失败可恢复 |
| AC15 | 同一用例跨环境/轮次执行 | 结果独立，历史用例内容可追溯 |
| AC16 | 创建/关联缺陷 | 关联到正确执行结果，失败重试不重复创建 |
| AC17 | 权限及并发冲突 | 未授权跨项目访问、只读写入被拒绝；并发修改不会静默覆盖 |
| AC18 | 历史自由脑图及转换 | 原数据可继续使用；转换前可预览，确认后不重复创建或误移动 |
| AC19 | 窄屏与大规模数据 | 详情可操作，状态清楚；通过预先记录的性能基准 |
| AC20 | 跨项目复制 | 预览目标字段和附件兼容；权限校验通过后生成新 ID，原用例及历史不变 |
| AC21 | 字段节点双向编辑 | 画布修改前置、步骤、预期与备注后右侧及列表一致；重排不串步骤 |
| AC22 | Excel/JSON 交换及重复 ID | 导出再导入字段语义一致；冲突有预览，确认前不写入，重试不重复 |
| AC23 | 回收站与版本恢复 | 恢复需权限及冲突校验，版本恢复形成新修订；不隐式恢复已删除目录 |
| AC24 | AI 差异建议及覆盖分析 | 新增/修改/删除/冲突可逐项确认；基于过期版本不覆盖新内容，覆盖建议与事实分开 |
| AC25 | 左侧导航与详情关联 | 模块定位、计数及移动一致；需求、接口测试、缺陷、评论、附件与历史按权限可读写 |
| AC26 | 评审任务及模式 | 名称、截止时间和状态可查询；单人最后有效结论、多人的否决规则及有建议提示正确 |

测试以浏览器实际路径及接口验证为主，覆盖对应权限、持久化、失败恢复和批量边界；实施前探索当前界面和可复用能力，不以测试代码存在代替验收通过。

## 11. 产品成功指标

上线后记录并对比上线前基线：

- 脑图创建的用例占全部新建用例的比例；单条用例从开始编辑到成功保存的耗时。
- AI 草稿采纳率，按采纳条数/有效展示草稿条数统计。
- 脑图评审任务完成率及按期完成率。
- 用例编辑与视图同步错误率，区分接口失败、冲突和显示不一致。
- 用例关联需求的覆盖率，统计基于真实关联，AI 建议不计入已覆盖。
- 导入与编辑导致的数据丢失事件数，目标为零。

埋点记录聚合行为和必要对象标识，不采集用例正文或附件内容；具体观察周期和改善目标在发布前基于基线确定。
