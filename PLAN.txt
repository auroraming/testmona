内置 AI 自动化测试能力基线（2026-10-30，规划未实施）
----------------------------------------------------

来源：[TestMona｜内置 AI 自动化测试能力规划（Web · Mobile · API）](https://app.notion.com/p/408e96dcbf1c814c921af639fc4b7bd9)

本文档是目标方案，不代表当前源码已具备对应能力。为避免与下方脑图产品版本混淆，本计划统一使用 AI-V1、AI-V1.1～AI-V1.4 表示 AI 自动化测试交付阶段。实施前先完成现状盘点、候选组件 PoC、安全评审和验收基线，不直接把第三方 MCP 工具等同于完整测试执行能力。

核心产品决策：

- [ ] 将 Web、Mobile、API AI 测试作为 TestMona 原生产品能力；普通用户只配置 AI Provider、目标环境和必要凭据，不手动安装 MCP 插件。
- [ ] TestMona 作为测试用例与执行记录的单一事实来源；列表、脑图和测试计划复用同一业务数据。
- [ ] MCP 只负责工具发现与调用；任务状态、断言、证据、重试、取消、用例/计划关联由 TestMona 自有执行模型负责。
- [ ] Web Runner、Mobile Runner 和 API Runner 可独立部署；不得把完整浏览器或设备环境塞入轻量主 API 进程。
- [ ] AI 用于首次探索、规划和失败分析；稳定流程经人工审核后固化为脚本，日常回归避免重复消耗大量 Token。

实施前技术决策与 PoC：

- [x] 盘点现有 AI Provider、测试执行、MCP、OpenAPI、测试计划、缺陷和报告模块，形成“复用/扩展/新建”清单；结论记录于 `docs/AI_AUTOMATION_ARCHITECTURE.md`。
- [ ] Web P0：验证 Playwright MCP 的 AI 探索能力，以及 Playwright Test + Chromium 的固定脚本回归和证据回传。
- [ ] Mobile P0/P1：验证 mobile-mcp 的设备发现与操作；评估 Mobilewright/Appium 作为固定脚本方案，明确 Android Worker 和 macOS/iOS Worker 的部署边界。
- [ ] API P0/P1：对 API Testing MCP 候选与原生 HTTP Runner 做一致性 PoC；Bruno MCP 仅作为集合回归候选，不在首期同时引入两套默认 API Agent。
- [ ] 扩展 P1：分别评估 k6、OWASP ZAP、Schemathesis 的许可证、维护状态、资源消耗、结果格式和隔离要求。
- [ ] 所有候选依赖在确定选型前记录版本、许可证、维护活跃度、已知安全风险及替代方案。

AI 自动化交付阶段：

- [ ] AI-V1：内置 MCP Client、Agent Runtime 和统一任务/结果接口。
  - [ ] AI Provider 支持模型选择、连通性检查和密钥加密存储。
  - [ ] Agent Runtime 支持用例理解、步骤规划、工具调用循环、预算、超时、取消和结构化错误。
    - [x] 基础循环：通过 AI Manager 生成单步 JSON 决策，只调用任务白名单内 MCP 工具；支持步骤上限、墙钟超时、Token 预算、逐步取消检查和结构化失败，不将工具调用成功等同于断言通过。
    - [ ] 任务集成：将真实用例上下文、循环步骤和断言持久化到统一任务/证据模型，并由 Runner 生命周期驱动。
  - [x] MCP Client 支持服务探活、工具发现、参数校验、调用、错误处理和超时；工具按任务最小权限授权。
  - [ ] 建立统一执行任务状态机、步骤结果、独立断言、证据、环境、Token/费用和审计模型。
    - [x] 第一批：新增 Web/Mobile/API 共用的 AI 自动化任务模型、项目权限隔离、用例/运行/环境关联、预算字段及创建/查询/取消接口；禁止任务配置内嵌密钥。
    - [x] 第二批：新增项目 Runner 注册、一次性令牌、哈希存储、轮换/禁用、按类型领取任务、90 秒租约、心跳续约、取消信号和幂等终态回报；步骤证据、审计和生产 Runner 仍待实现。
    - [x] 第三批：新增不可变有序证据模型，支持步骤、断言、日志、截图、Trace 和网络证据批量上报、幂等重试及项目内查询；二进制文件仅保存受控存储引用，拒绝外部 URL、文件系统路径、超大载荷和敏感字段。
    - [x] 第四批：任务创建/取消、Runner 注册/令牌轮换/禁用及终态回报写入既有项目审计流，Runner 事件保留独立身份元数据；远程 MCP 增加任务创建、查询、取消和证据读取工具，但不暴露内部 Runner 协议。
  - [ ] 验收：通过统一接口发现并调用内置测试工具；工具调用成功不会自动把用例判为通过。
- [ ] AI-V1.1：Playwright MCP + Playwright Test + Chromium Web Runner。
  - [ ] 提供独立 Docker Web Runner，预装兼容版本 Chromium 和系统依赖，具备资源、网络和权限隔离。
  - [ ] 支持 Web AI 探索、截图/Trace/网络日志采集，以及固定脚本批量回归和 CI 调用。
  - [ ] 验收：部署后可执行一条真实 Web 用例，并将断言、截图、Trace、日志、耗时关联回用例、计划和执行轮次。
- [ ] AI-V1.2：mobile-mcp + Mobile Runner + 设备发现。
  - [ ] Worker 注册 Android/iOS 真机或模拟器，提供设备能力、占用锁、心跳、授权和离线状态。
  - [ ] 无可用设备时给出明确提示；iOS 能力明确依赖 macOS/Xcode，不承诺任意 Docker 主机开箱即用。
  - [ ] 验收：在至少一台 Android 和一台 iOS 可用设备上执行用例并回传截图、步骤和错误；无法提供某类设备时记录环境限制而非虚假通过。
- [ ] AI-V1.3：API Agent PoC + 原生 HTTP Runner + 报告。
  - [ ] 复用现有 OpenAPI/Swagger 导入结果生成请求、断言和边界场景；凭据通过安全引用注入，不写入用例正文或日志。
  - [ ] API MCP 与原生 HTTP Runner 对同一用例输出统一结果结构，并支持接口级超时、重试、脱敏和环境变量。
  - [ ] 验收：从 OpenAPI/Swagger 生成并执行真实 API 用例，断言响应状态/结构/关键字段，结果可追溯到规范、用例和执行轮次。
- [ ] AI-V1.4：探索转固定脚本、失败分析和 Token 指标。
  - [ ] AI 探索结果可生成人工审核的固定脚本版本，记录来源、修改、运行环境和回滚点。
  - [ ] 基于日志、请求、截图和断言生成失败根因建议；建议与正式缺陷创建/关联分离，必须人工确认。
  - [ ] 按任务记录输入、缓存、输出 Token 和可用费用信息，支持预算告警和中止。
  - [ ] 验收：同一稳定流程可脱离逐步 LLM 调用重复执行；失败证据完整、脚本可回滚、Token 数据可审计。
- [ ] 后续专项：在统一 Runner、结果和权限框架下扩展 Bruno、k6、ZAP、Schemathesis，不建立平行任务模型。

跨阶段安全与运行约束：

- [ ] 默认禁止生产环境、真实资金和破坏性操作；环境、目标域名、账号和网络范围采用显式白名单。
- [ ] 凭据加密存储、运行时短期注入、日志与截图脱敏；敏感操作需要人工确认并写入审计记录。
- [ ] Scheduler 支持队列、并发上限、重试、取消、Runner 心跳、设备锁和幂等结果回传。
- [ ] Runner 使用最小权限、资源限制和网络隔离；主后端不得直接信任 Runner 上报的“通过”，必须按断言规则归档结果。
- [ ] 失败、超时、Runner 中断和重复回调均有可恢复状态，不产生重复执行记录或悬空设备锁。

首期验证清单：

- [ ] 完成现有模块复用评估并形成架构决策记录。
- [ ] 通用 MCP Client 完成探活、发现、调用、参数错误和超时验证。
- [ ] 预装 Chromium 的 Web Runner 在 Docker 环境启动并完成一次页面测试。
- [ ] Playwright Test 固定脚本执行后，断言和证据正确回传 TestMona。
- [ ] Android/iOS Worker 能注册设备，并验证无设备、设备占用和设备离线提示。
- [ ] API MCP 候选与原生 HTTP Runner 对同一用例产生一致的结果数据。
- [ ] 日志、截图、Trace 与用例 ID、测试计划、执行轮次正确关联。
- [ ] Token 预算、敏感操作审批、Runner 隔离、失败重试和取消均有实际验证记录。

一、目标与范围
------------

目标：在项目范围内提供可视化 Mind Map，允许用户在任意脑图节点上关联一个或多个现有测试用例，并能从脑图跳转到测试用例详情、从测试用例查看其所在脑图。

本期包含：
1. 脑图列表、新建、编辑、删除（沿用已有 test_mindmaps 后端能力）。
2. 节点的新增、改名、移动、删除、折叠与布局保存。
3. 节点关联/解除关联项目内现有测试用例。
4. 关联用例搜索、摘要展示、详情跳转、失效关联提示。
5. 测试用例详情页展示反向关联的脑图和节点。
6. 权限、项目隔离、审计友好的 API 与自动化测试。
7. 增加简体中文（zh-CN）界面语言，并可在首次设置和系统设置中切换。
8. 增加测试用例目录树，支持分层组织、移动、筛选和目录级用例计数。
9. 支持导入 OpenAPI 3.x / Swagger 2.0 规范，预览并转换为可编辑的测试用例。

本期不包含：
1. 从脑图节点直接批量生成完整测试步骤（可作为后续迭代）。
2. 实时多人协同编辑与冲突合并。
3. 脑图导入/导出 XMind、FreeMind 等格式。
4. 跨项目关联测试用例。

二、现状与设计结论
------------------

1. 后端已有 test_mindmaps 模型、基础 Schema、CRUD 和 /test-mindmaps/ API。
2. 现有 mindmap_data 是 JSON，可保存节点和布局，但目前没有前端页面。
3. 当前没有脑图与测试用例的规范化关联表。
4. 不应只把 test_case_id 写入 mindmap_data：这样无法可靠执行外键约束、反向查询、项目隔离、删除处理和关联统计。
5. 采用“JSON 保存画布结构 + 独立表保存业务关联”的混合方案：
   - mindmap_data：节点 ID、父子关系、坐标、折叠状态、样式等纯画布数据。
   - test_mindmap_test_case_links：脑图节点与测试用例的业务关联，作为唯一事实来源。

三、数据模型与迁移
------------------

新增表 test_mindmap_test_case_links：

- id：主键。
- mindmap_id：外键 test_mindmaps.id，删除脑图时级联删除关联。
- node_id：稳定的字符串节点 ID，不使用节点标题作为标识。
- test_case_id：外键 test_cases.id，删除测试用例时级联或由软删除逻辑保留并标记不可用；实现时统一现有软删除语义。
- created_by：建立关联的用户。
- created_at：建立时间。
- 唯一约束：(mindmap_id, node_id, test_case_id)。
- 索引：mindmap_id、test_case_id、(mindmap_id, node_id)。

模型关系：

- TestMindmap 增加 test_case_links relationship。
- TestCase 增加 mindmap_links relationship。
- 新增 TestMindmapTestCaseLink 模型。

迁移要求：

- 新建 Alembic migration，兼容 SQLite、MariaDB/MySQL、PostgreSQL。
- 使用项目 migration_helpers 保持迁移幂等。
- downgrade 可安全删除索引和关联表。
- 不修改或破坏已有 mindmap_data。

四、Mind Map 数据格式
--------------------

为 mindmap_data 定义并校验版本化结构：

{
  "version": 1,
  "rootId": "node-...",
  "nodes": [
    {
      "id": "node-...",
      "parentId": null,
      "title": "登录功能",
      "position": {"x": 0, "y": 0},
      "collapsed": false,
      "style": {}
    }
  ]
}

约束：

- node.id 在单个脑图内唯一且保存后保持稳定。
- 根节点必须存在，普通节点的 parentId 必须指向现存节点。
- 禁止循环父子关系。
- 限制节点数量、标题长度和 JSON 体积，避免异常大请求。
- 删除节点时，同一事务内删除该节点及其所有后代的用例关联。
- 更新 mindmap_data 时，后端清理已不存在 node_id 的孤立关联。

五、后端 API
------------

整理并扩展现有接口：

1. GET /test-mindmaps?project_id={id}
   - 返回脑图摘要、节点数、关联用例数、更新时间。
   - 严格按 project_id 检查当前用户读取权限，修正当前列表接口只做全局 read 检查的问题。

2. POST /test-mindmaps
   - created_by 从 current_user.id 获取，不接受客户端伪造。
   - 初始化 version=1 的根节点。

3. GET /test-mindmaps/{mindmap_id}
   - 返回 mindmap_data 和各节点的关联用例摘要。

4. PUT /test-mindmaps/{mindmap_id}
   - 保存名称、描述和画布结构。
   - 校验数据格式，并清理被删除节点的关联。

5. DELETE /test-mindmaps/{mindmap_id}
   - 延续软删除脑图；关联记录应不可再被查询，必要时同步清理。

6. GET /test-mindmaps/{mindmap_id}/nodes/{node_id}/test-cases
   - 返回关联用例列表，包括 id、project_seq、title、priority、status、suite/section 摘要。

7. POST /test-mindmaps/{mindmap_id}/nodes/{node_id}/test-cases
   - 请求：{"test_case_ids": [1, 2, 3]}。
   - 校验节点存在、测试用例未删除、脑图和用例属于同一项目。
   - 幂等批量关联并返回最新列表。

8. DELETE /test-mindmaps/{mindmap_id}/nodes/{node_id}/test-cases/{test_case_id}
   - 解除单个关联。

9. GET /test-cases/{test_case_id}/mindmaps
   - 返回用例关联的脑图及节点摘要，用于测试用例详情页反向展示。

权限规则：

- 查看脑图和关联：项目 read。
- 编辑画布、关联和解除关联：项目 write。
- 删除脑图：项目 delete。
- 所有接口均根据服务端查出的实体 project_id 校验，不能信任请求体中的 project_id。

10. OpenAPI 格式导入并转换为测试用例
   - 提供文件上传和文本粘贴两种入口，首版支持 JSON、YAML 格式的 OpenAPI 3.0、3.1 与 Swagger 2.0。
   - 采用“两阶段导入”：第一阶段只解析并生成预览，不写数据库；第二阶段由用户确认选择后批量创建测试用例。
   - 解析预览展示规范标题、版本、servers/basePath、tags、path、HTTP method、operationId、摘要、参数、请求体、安全要求和响应定义。
   - 用户可按 tag、path、method 搜索筛选并多选接口；可指定目标测试套件与目录，未指定目录时放入所选套件根级。
   - 每个 operation 默认生成一组可编辑草稿，至少包含：
     1. 正常请求用例：根据必填参数、示例/default/enum 和成功响应生成。
     2. 缺少必填参数用例：覆盖 path/query/header/cookie/request body 必填字段。
     3. 参数边界用例：根据 minimum/maximum、minLength/maxLength、pattern、enum、format 等约束生成。
     4. 鉴权用例：存在 security 要求时生成未认证或无效凭证场景，但不得生成或保存真实密钥。
     5. 错误响应场景：根据规范中声明的 4xx/5xx 响应生成；不凭空假设未声明的业务语义。
   - 将接口方法和路径写入测试用例 reference，例如“POST /v1/users”；标题优先使用 summary，其次 operationId，再回退为 method + path。
   - 测试步骤使用现有多步骤结构：准备请求数据、发送请求、校验状态码、校验响应 schema/关键字段；预期结果引用规范中的响应状态和 schema 约束。
   - 生成的草稿默认标记来源元数据：规范指纹、operationId、method、path、源文件名和导入时间，便于去重和后续重新导入。
   - 原始规范不可直接作为永久业务数据塞入测试用例正文；若需要保存导入记录，新增受限的 import operation 记录及规范摘要/指纹，不保存敏感 header 示例。
   - 用户可在预览页逐条编辑标题、优先级、类型、前置条件、步骤、预期结果、标签、目标目录，并可删除不需要的草稿。
   - 提供生成策略选项：仅正常场景、正常 + 必填校验、完整约束覆盖；预览中显示预计生成数量，避免一次产生过多用例。
   - 设置单次上传大小、path 数量、operation 数量和最终草稿数量上限；超限返回明确提示并允许用户缩小选择范围。

OpenAPI 解析与安全：

- 使用成熟且许可证兼容的 OpenAPI 解析/校验库，统一将 Swagger 2.0 和 OpenAPI 3.x 归一化为内部 operation 模型。
- 支持本地 $ref 与同一文档内组件引用，并检测循环引用；首版默认禁止自动访问远程 $ref，避免 SSRF、内网探测和不受控下载。
- 若后续支持 URL 导入，必须单独启用并复用 webhook/private URL 安全策略，限制协议、重定向、DNS 解析结果、响应大小和超时。
- YAML 使用安全加载模式，禁止任意对象构造；解析错误需返回带位置和字段路径的可读信息。
- 对 schema 递归深度、数组示例规模、组合关键字（allOf/oneOf/anyOf）分支数量设置上限，防止资源耗尽。
- 不执行规范中的任何脚本、链接、callback、webhook 或示例请求；导入只做静态解析和草稿转换。
- 对 authorization、api-key、token、secret、password 等字段的 example/default 做脱敏，绝不写入日志和测试用例。

OpenAPI 去重与重新导入：

- 新增稳定 source_key，建议由规范指纹 + method + normalized path + operationId 组成，并记录到导入映射表。
- 确认导入时支持“跳过已存在”“创建副本”“更新此前导入的用例”三种模式，默认跳过已存在。
- 更新模式只更新由导入器维护的字段，用户手工编辑过的内容必须通过预览差异确认，不能静默覆盖。
- 同一批次使用幂等键，网络重试不得重复创建测试用例。
- 批量创建使用事务或可追踪的分块事务；失败时返回成功、失败和跳过的逐项结果，并可安全重试。

OpenAPI 后端 API：

- POST /import-export/openapi/preview：接收 multipart 文件或规范文本，解析后返回规范摘要、operations、警告和预览 token，不创建用例。
- POST /import-export/openapi/generate-preview：接收 preview token、选中的 operation keys、生成策略和目标套件/目录，返回可编辑测试用例草稿。
- POST /import-export/openapi/commit：接收确认后的草稿、目标位置、duplicate_mode 和 idempotency_key，批量创建/更新用例。
- GET /import-export/openapi/operations/{operation_id}：返回导入任务状态和逐项结果，适用于较大批次。
- 预览 token 短时有效、绑定用户和项目，不包含可被客户端篡改后绕过项目权限的可信字段。
- 所有阶段校验项目 write 权限、目标套件/目录归属和测试用例功能开关。

OpenAPI 前端流程：

- 在测试用例导入入口增加“OpenAPI / Swagger”选项。
- 使用分步界面：上传规范 → 检查结果 → 选择接口 → 选择生成策略 → 编辑草稿 → 确认导入 → 查看结果。
- 解析警告与错误分别展示；警告允许继续，致命错误阻止进入下一步。
- operation 列表支持 tag 分组、method 彩色标识、path 搜索、全选当前筛选结果和预计生成数量。
- 草稿编辑复用现有测试用例表单/步骤编辑能力，避免维护两套字段校验。
- 导入结果提供“查看已创建用例”“重试失败项”和“返回目标目录”。
- 所有新增文案加入 en、fa、ar、zh-CN 语言包，并保证长 path、schema 名称和 LTR/RTL 混排可读。

七、一致性与边界情况
--------------------

1. 测试用例只能关联到同项目脑图，服务端强制校验。
2. 重命名、移动节点不会影响关联，因为关联键使用稳定 node_id。
3. 删除节点时必须同时清理后代节点关联；UI 需二次确认并显示受影响用例数。
4. 测试用例软删除后不出现在新建关联搜索中；已有关联按产品语义显示失效状态或清理。
5. 脑图软删除后反向查询不得返回该脑图。
6. 重复提交同一关联不报 500，返回幂等成功。
7. 无权限、跨项目 ID、无效 node_id、无效 test_case_id 分别返回明确的 403/404/422。
8. API 不允许客户端指定 created_by。
9. 对 mindmap_data 做结构验证和体积限制，避免任意 JSON 或超大载荷。

3. 刷新页面后布局和关联仍完整。
4. 点击关联用例能打开正确详情页。
5. 测试用例详情可返回对应脑图节点。
6. 项目 B 用户无法看到或关联项目 A 的数据。
7. 删除节点后其关联同步消失，其他节点不受影响。
8. 用户选择“简体中文”后，导航、脑图页面、测试用例关联交互和通用设置立即显示中文，刷新后不回退英文。
9. 用户可创建多级测试用例目录，将单个或多个用例移动到目录，并按当前目录或包含子目录查看用例。
10. 刷新页面或复制筛选链接后仍定位到相同目录；目录计数、路径和测试用例列表保持一致。
11. 用户上传 OpenAPI/Swagger JSON 或 YAML，筛选接口并选择生成策略后，可预览、编辑并批量创建到指定测试套件/目录。
12. 重复导入不会意外创建重复用例，恶意或不受支持的规范会被安全拒绝并显示可理解的错误。

十、完成标准（Definition of Done）
---------------------------------

- 数据库迁移可在三种支持的数据库上正常执行。
- 所有新增 API 有权限与项目隔离保护，并有测试覆盖。
- 用户能创建、编辑、保存脑图并在节点上关联/解除测试用例。
- 页面刷新后数据不丢失，测试用例详情可反向查看脑图。
- 不存在跨项目关联、孤立关联和重复关联。
- 前端构建、后端相关测试与新增前端测试全部通过。
- 新增 UI 文案完成国际化，不引入明显可访问性回退。
- 简体中文可在首次设置和通用设置中选择并持久化，中文语言包通过完整性测试。
- 测试用例目录支持多级组织、稳定排序、批量移动和可分享筛选，且不出现跨项目、跨套件或循环层级数据。
- OpenAPI/Swagger 导入具备安全预览、可控生成、人工确认、幂等提交和重复导入策略，生成结果可追溯且不会泄露规范中的敏感示例。
- 外部 MCP 客户端可通过 `/mcp` 和个人 API Token 连接；无效、过期或撤销令牌无法握手，且不再依赖本地 stdio 进程。
